# G7A, official PathCond + Adam versus Adam and G5 (preregistered 2026-10-28)

**Research question:** Can the *authors' actual PathCond initialization* improve Adam's robustness to positive ReLU neuronwise reparameterization without hurting normal-coordinate accuracy? G6 showed G5 better protects trajectories but loses to tuned Adam on test cross entropy.

## External implementation / compatibility
Pin the original implementation to [Artim436/pathcond commit 535b202e3476c64d5e7e9ec5e817344fb5cfd787](https://github.com/Artim436/pathcond/tree/535b202e3476c64d5e7e9ec5e817344fb5cfd787), license CC-BY-4.0, and call `from pathcond.pathcond import rescaling_path_cond` **without replacing/reimplementing its algorithm**. It depends on PyTorch and imports torchvision/tqdm. Do not vendor author code, silently fall back to a heuristic, or call a homegrown approximation PathCond.

The upstream `compute_B_mlp` assumes ordinary sequential affine layers, and its residual handling targets different architectures. Thus **plain sequential ReLU MLPs only** in G7A. One-Matrix ResMLP from G1–G6 is **out of scope**. All three methods use the *same PyTorch architecture*, feature pipeline, initialization and minibatch order. G5 is ported from the existing NumPy G5 frame update to PyTorch and must pass a one-step cross-framework numerical equivalence test before interpreting its results.

## Protocol, frozen before any training
- Offline tasks: sklearn handwritten digits (10 classes, 64 features) and generated balanced-ish concentric circles (2 classes, 2 features; radius .55), with **stratified 60/20/20** train/validation/test split, train-only StandardScaler. Data-loader seed fully specified.
- Architecture: plain ReLU width 32, hidden depth 3 and 6, output linear; float64 CPU. No dropout/weight decay, ReLU after hidden layers only. The implementation may use `nn.Sequential` with `nn.Linear` and `nn.ReLU`.
- Three methods: (1) Adam, (2) **official PathCond once at initialization** then *the same Adam*, (3) the original G5 clipped activity-frame update transcribed to PyTorch and independently tested against NumPy. A PathCond candidate that fails to preserve initial logits to max absolute error 1e-7 is a **failure**, not a valid result.
- Training: 100 minibatch updates, batch64, replacement sampling with RNG 10000+seed, identical indices within conditions, record test/validation cross entropy and accuracy at step100. `torch.set_num_threads(1)`.
- Learning-rate grid (2 choices each): Adam/PathCond+Adam {0.001,0.003}; G5 {0.01,0.05}, cap=1.0. Methods have **equal 2-candidate trial budget**, no extra hyperparameter tuning of PathCond's default 10 rescaling iterations. **Tuning seeds 40,41** only. Select by mean validation CE, treating failures as +infinity; tie smaller rate.
- **Heldout seeds 50,51,52** (3 independent seeds), never used for rate selection or code debugging. 2 tasks x 2 depths x 3 methods x 3 heldout = 36 ordinary-coordinate holdout runs. Test CE, accuracy, finite failures, wall-clock time, and initial-function preservation. For each heldout seed and each method, run a function-equivalent *neuronwise positive diagonal rescaled* copy at initialization: factors log-spaced 1/8..8 permuted deterministically, independent hidden-layer scales. Evaluate paired logits on the heldout test set after steps {0,1,25,50,100}, and record failure rates and drift. **These are stress tests**, not evidence of function-intrinsic superiority.
- H1, strict integration quality: 12 PathCond+Adam holdout runs **all** return a finite, genuinely rescaled network with initial max-logit error <1e-7 and classification unchanged (no silent no-op).
- H2, predictive benefit: PathCond+Adam has lower mean heldout **test cross-entropy** than ordinary Adam in at least **3 of the 4** task/depth cells. Report all outcomes, do not adjust threshold.
- H3, gauge benefit: PathCond+Adam has smaller mean terminal gauge logit gap (failure counted as +infinity) than plain Adam in at least **3 of 4** cells. This is a *hypothesis*, not a guaranteed consequence of the paper.
- Secondary: G5 relative performance; accuracy and wall-time including PathCond overhead; and improvement at matched wall time if feasible. Do not select on test sets.
- Technical controls: initial logits bit-identical for Adam/G5 before training, PathCond preserves function, PyTorch G5 first-step update matches NumPy G5 with shared initialization and exact minibatch, learning rate 0 is no-op, gauge transformation preserves function for all models. No skipped failures, no retuning after holdout. Any result under code changes must disclose and restart confirmation with genuinely fresh seeds.

## Practical limitation
G7A is a **small but clean benchmark**. It does not include the paper's reported convnets, ResNets, nor CIFAR-10, and does not establish general superiority. At its end, report negative/null findings prominently. PathCond's runtime includes the official initialization transformation; G5's frame computation adds work at *every* step. Upstream failures/incompatibilities should be logged honestly and not replaced by a different algorithm.

## Protocol clarification before any held-out G7A execution
For stress tests the positive neuronwise coordinate transform is applied **before** optional PathCond preprocessing. In the PathCond+Adam arm the same upstream `rescaling_path_cond` function is invoked separately on each equivalent unconditioned initialization, not on the already-conditioned network followed by a new distortion. This evaluates its claimed conditioning as a remedy for arbitrary starting coordinates. In all arms the preprocessing-equivalent logits must be preserved before optimization. The reference G5 PyTorch port must pass exact one-step NumPy comparison before training. The upstream git SHA above is immutable and PyTorch's default tensor dtype is set to float64 (the official initializer uses an implicit dtype for its dummy input). No alteration to H1/H2/H3 success thresholds, seeds, rates or tasks.

## Audit addendum: failed upstream smoke, 2026-10-28 (before any tuning or held-out training)
The first clean GitHub runner installed the pinned official PathCond source and passed the G5 PyTorch/NumPy check, but **the original PathCond changed pre-training logits by 4.32671726002809e-7** on the first smoke model. It violates the previously locked H1 preservation threshold of 1e-7. The original smoke run is [GitHub Actions 40791460819](https://github.com/maaronfanberg-lab/me-/actions/runs/40791460819). No tuning runs or held-out runs were performed because preflight stopped before training.

**We do not relax or erase the H1 criterion.** To learn from the attempted application of the real upstream method, change the harness to record finite nonzero rescalings and their numerical logit mismatch, but permit **exploratory** training when the mismatch is below a separately disclosed practical tolerance of 1e-3. H1 is still computed using the original 1e-7 threshold and *must fail* for any heldout PathCond run exceeding it. No methods, seeds, architectures, LRs, training steps, H2/H3 pass thresholds, or data partitions change. H2/H3 comparisons remain prospective with respect to test data because none has been examined, but must be interpreted in light of H1's floating-point discrepancy. No silent fallback to a custom conditioner.

In gauge stress tests, separately conditioned gauges can differ numerically: record postconditioning logit discrepancy and all later gaps even when above 1e-7. Only nonfinite outputs, invalid module state, or a discrepancy above the separately disclosed 1e-3 practical threshold stop that run. Report initial mismatch independently of later gauge divergence.
