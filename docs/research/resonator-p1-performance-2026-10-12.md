# RESONATOR P1 — phone performance: stop computing silence, measure load on the device (2026-10-12)

Preview only (`apps/resonator-next.html`); generated by `qa-resonator/patch_p1.py` (verified edits;
aborts on any mismatch). Also new: Safari's engine on GitHub (`qa-resonator/webkit_check.py`,
workflow "RESONATOR WebKit").

## 1. Observed problem
- Stage 4's note: 8 voices on String ran at about 110% of real time on the dev machine. A phone that
  cannot keep up crackles; the page could not tell, because underruns were detected only in the
  rarely used buffered fallback.
- Measured before the change (V8, dev machine, steady state, fresh process each): Tank with 8 voices
  and one note a second used 89% of real time; String with 8 voices, 34%; an idle Tank, 14%.
- Profile: the physics step `advance()` took 57–81% of the time; with effects on, the garbage
  collector took 10%, because the effects returned a new array for every audio sample.

**Research question.** Can the engine stop spending time on silence, and measure its own load on the
phone, without changing the sound?

**Pre-change baseline.** The "before" column of the cost table in section 10. The page had no load
reading in AudioWorklet mode.

**Validation criteria (set before the change).**
- With sleep and governor off, output bit-identical to the previous preview on every setup.
- With sleep on, the largest difference below −100 dBFS, and voices really asleep.
- The governor sheds smoothly (no larger sample step than unmuted), respects its limit, and recovers.
- The CPU estimate within 10% of a precise clock.
- All earlier stage suites pass, in Chromium and in WebKit.

**Sources (read 2026-10-11/12).**
- W3C, *Web Audio API 1.0* (Recommendation), "Rendering an Audio Graph" and AudioWorklet: rendering
  proceeds in 128-frame quanta.
- IEEE 754-2019 §6.3 (the sign of a sum of zeros): used in the exactness argument.
- Anukari devlog index (anukari.com/blog/devlog): voice stealing "prefers released notes", 2024-07.
- WebKit 26.0 via Playwright 1.56 (GitHub Actions, 2026-10-12): measured in this work.

## 2–5. Evidence and mechanism
- **Where the time went.** `advance()` simulated every voice on every substep, including voices that
  had never been struck. The engine already marked decayed voices "off" for voice allocation but kept
  simulating them.
- **Skipping a voice at rest is exact.** A voice exactly at rest (positions equal to rest positions,
  velocities zero) computes, spring by spring: dx equals the rest vector, so L = a exactly; the
  transverse term is T·(ux − su) = T·0; the longitudinal term is kL·(L − a) = 0; the damping term is
  c·0. Every force is +0 (checked down to the sign of zero, which matters for bit-identity), so
  velocities stay +0 and positions stay at rest. Skipping such a voice therefore changes nothing,
  bit for bit, as long as nothing pushes it (strike pulses, oscillator or microphone force, wind,
  bow, feedback). Every write to positions and velocities in the engine was listed; each either
  re-establishes exact rest (build, hard reset, sleep) or clears the flag (rewind, moving a mass).
- **Sleep (page-enabled).** A voice whose motion has died below 1e-8 of its own scale (velocity
  relative to its pitch and the body's size; displacement relative to the body's size) is set exactly
  to rest and then skipped. Worst-case gain to the output (level, shape trim, saturation slope)
  puts this near −110 dBFS; measured worst case −134 dBFS.
- **Measuring load on the device.** An AudioWorklet's `process()` must return within one render
  quantum (128 frames; 4 ms at 32 kHz) or the output glitches (Web Audio API, W3C, "Rendering an
  audio graph"). AudioWorkletGlobalScope offers no high-resolution clock, so the engine sums
  `Date.now()` differences around `process()` over 0.25 s of audio. The 1 ms steps average out:
  against `performance.now()` around the same work, 22 readings averaged 18.6% vs 18.6%.
- **Governor (page-enabled).** Real-time synthesizers shed voices rather than miss deadlines (voice
  stealing; e.g. Anukari's voice stealing "prefers released notes", devlog 2024-07). Here: two
  consecutive readings above 85% mute the quietest voice that is neither the newest note nor a held
  key. Muting is physical, extra damping of 60 dB in 15 ms like a hand on a string, so there is no
  click. The voice then sleeps, and fewer voices may ring at once. The limit rises again after 2 s
  under 60%.
- **No new array per sample.** The effects now write their results into fields (same values).

## 6–8. Competing explanations, limits, context
- **A number that looked wrong, investigated.** In the first timing table, sleep sometimes *raised*
  the cost (idle String 2.3% → 9.6%). Measured warm and interleaved, idle String was 1.2–1.7% either
  way; in separate processes idle Tank was 1.44% (off) and 1.70% (on) with identical profiles. The
  swings came from running several engine copies in one test process, where V8 shares compiled code
  between them. The phone runs one engine, so every timing now comes from a fresh process
  (`p1_cost_one.mjs`).
- **A silent Tank in the first WebKit check was a test artefact.** An offline render does not deliver
  the engine's messages while it runs; a fixed 250 ms wait was shorter than Tank's tuning, so the note
  arrived after the render. With the check waiting for the engine's `ready`, Tank matches Node
  exactly. Recorded in `qa-resonator/README.md` as a ratchet.
- **Limits.** Dense playing with every voice ringing gains less (Tank 4 voices 45% → 35%). That is
  the case the governor protects. No phone has been measured: the Copy report now carries the
  phone's own CPU reading, highest reading, voices ringing, voices let go and voices asleep.
- **Safari's engine.** WebKit 26.0 on Linux and on macOS (Apple silicon) runs both pages with live
  audio. JavaScriptCore's output is bit-identical to Node's on 8/8 shapes. Tank's freeze is
  25–39 ms on the preview vs 363–435 ms on the live page, and one String voice runs 71× real time
  on Apple silicon.

## 9. Implementation mapping
- **Engine.**
  - New state: `vRest`, `vMute`, `perfSleep`, `perfGov`, `vCap`, CPU accumulators.
  - New messages: `perf {sleep, gov}`, `perfTest {c}` (a test hook that drives the governor).
  - `advance()` skips voices at rest and damps muted voices.
  - New methods: `sleepCheck()` (every 1024 samples), `governCpu()`, `shedVoice()`, `awakeCount()`.
  - `pickVoice()` reuses a ringing voice at the governor's limit.
  - `process()` now times `processInner()`.
  - The frame message carries `cpu`, `cpuMax`, `aw`, `cap`, `ga`, `sl`.
- **Page.**
  - Sends `perf {sleep:1, gov:1}` after start.
  - Shows "CPU nn%" in the readout and explains when a voice is let go.
  - Copy report gains a `cpu:` line.
